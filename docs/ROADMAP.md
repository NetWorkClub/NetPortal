# Дорожная карта разработки NetPortal (Roadmap)

Разработка разбита на последовательные фазы. Каждая фаза завершается проверяемым результатом и рабочими артефактами без раздувания скоупа в один заход.

---

## Фаза 0: Фундамент, архитектура и конвейер агентов [Завершена]

**Цель:** Создать чистую базу в `NetPortal`, зафиксировать архитектуру, правила для AI-агентов и сквозной конвейер разработки.

**Состав работ:**
- Инициализация монорепозитория (`go.work`, `core/`, `desktop/`, заглушки `ui/`, `android/`, `ios/`), `.gitignore`, MIT `LICENSE`, двуязычный `README.md`.
- Агентная документация: `AGENTS.md`, мосты (`GEMINI.md`, `CLAUDE.md`, `.cursorrules`) и 5 проектных скиллов в `.agents/skills/`.
- Документация продукта и архитектуры: `docs/VISION.md`, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`, `docs/adr/0001..0004`.

**Критерии готовности (DoD):**
- [x] Структура репозитория создана и описана.
- [x] `go vet ./core/... ./desktop/...` проходит с кодом 0 без ошибок.
- [x] Во всех файлах отсутствует декоративные эмодзи (Zero-Emoji Policy).

## Фаза 1: Дизайн-система и базовый модульный UI/UX [Завершена — базовый этап]

**Цель:** Проработать визуальный язык, навигацию и эргономику всех ключевых сценариев **до написания продакшн-кода UI** (Desktop + Mobile/Android).

**Состав работ:**
- `docs/DESIGN_SYSTEM.md`: цветовые токены, типографика, состояния узлов/ошибок/конфликтов, иконография (чистый SVG без эмодзи), адаптивные паттерны (Desktop Sidebar <-> Mobile Bottom Nav <-> Android TV focus), правила WebKitGTK 4.1 (`appearance: none`, `color-scheme`).
- Интерактивный модульный прототип интерфейса в `ui/` (Angular 21 Standalone + Signals + Zoneless + Modular SCSS + `MockTransport` + JSON i18n):
  - Главный экран (Simple Mode + быстрые индикаторы);
  - Каталог подписок и нод с оффлайн-пингом ДО подключения (Happ-like UX);
  - Визуальный конструктор маршрутизации (домены, суффиксы, IP-пулы, процессы/программы, цепочки Sticky-Fallback);
  - Мастер генератора WARP / MASQUE и Psiphon;
  - Экран DPI-обхода (ByeDPI / Zapret), Smart Hosts/DNS и панель ConflictGuard.

**Критерии готовности (DoD):**
- [x] Прототипы открываются и корректно адаптируются на ширине Desktop (`1200x760`, `960x760`) и Mobile (`390x844`).
- [x] Базовый дизайн и модульная структура `ui/` согласованы как рабочая основа с потенциалом к точечной доработке в процессе использования и интеграции с ядром.

## Фаза 2: MVP — Кроссплатформенное ядро, демон и AmneziaWG 2.0 / 3.0 / 3.1

**Цель:** Получить первый рабочий сквозной релиз на **Windows**, **Linux (Wayland / X11)** и **Android**, полностью заменяющий классический desktop-клиент AmneziaWG.

**Целевые платформы:** Windows x64, Linux amd64 (`.deb` + `.tar.gz`), Android (`.apk`).

**Состав работ:**
- `core/api` и `core/storage`: базовая модель источников/туннелей, настроек, журнала событий.
- `core/parser`: полный парсер и сериализатор WireGuard / AmneziaWG 2.0 / 3.0 / 3.1 (`.conf`, `vpn://` от Amnezia, проверка всех полей `Jc..I5`, `HeaderProtectionKey`, `RandomTrailers`, `DisableCookies`, диапазонов `H1-H4`).
- `core/engine/awg`: обертка над `github.com/amnezia-vpn/amneziawg-go/v3` для Desktop TUN и Android `VpnService` fd.
- `core/cmd/netportal-daemon`: Named Pipe (Windows Service / single-UAC session) и UDS (Linux systemd / single-`pkexec` session).
- `desktop/`: Wails v2 (`-tags webkit2_41`, `WEBKIT_DISABLE_DMABUF_RENDERER=1`, трей, флаг `--web`).
- `ui/`: интеграция реальных транспортов (`WailsTransport`, `AndroidBridgeTransport`, `HttpWsTransport`) вместо `MockTransport` поверх уже готовых модульных экранов Angular 21 и SCSS-системы (экраны туннелей, инспектор AWG, живые логи и трафик).
- `android/`: базовый Kotlin `VpnService` + `WebViewAssetLoader` + `netportal-core.aar` (`gomobile bind`) + Quick Settings Tile.
- GitHub Actions CI/CD для Windows (`.exe` + NSIS), Linux (`.deb` + `.tar.gz`), Android (`.apk`).

**Критерии готовности (DoD):**
- [ ] Импорт и запуск реальных конфигов AWG 2.0, 3.0 и 3.1 на Windows, Linux (Wayland / X11) и Android без ручной настройки прав бинарников.
- [ ] Корректное закрытие/сворачивание в трей и восстановление DNS/маршрутов при аварийном выходе.

## Фаза 3: Универсальный прокси-агрегатор, оффлайн-пинг и Конструктор маршрутизации

**Цель:** Превратить NetPortal в полноценный универсальный агрегатор (VLESS, Hy2, MASQUE) с пре-коннект пингом уровня Happ и визуальным конструктором правил без скрытых дефолтов.

**Состав работ:**
- `core/engine/singbox` (+ адаптер `mihomo`/MASQUE для RFC 9484 CONNECT-IP и Clash YAML).
- `core/parser`: подписки (`vless://`, `vmess://`, `trojan://`, `hy2://`, `tuic://`, `ss://`, Clash Meta YAML, sing-box JSON, MASQUE JSON/YAML, base64-списки).
- `core/probe`: двухуровневый пре-коннект пробер (массовый/выборочный TCP/TLS пинг + эфемерный no-TUN URL-test + антибот/капча проверка) — все работает ДО включения VPN.
- `core/router`: ИР конструктора, компиляция в конфиги движков, списки доменов/суффиксов/regex/внешних списков (`iplist.opencck.org` и др.)/IP-пулов/процессов (Win+Linux)/приложений (Android).
- Реализация стратегии `sticky_fallback` (удержание pinned-ноды с кросс-протокольным резервом по healthcheck) и тестера правил в UI.

**Критерии готовности (DoD):**
- [ ] После вставки ссылки подписки все ноды видны и пингуются (включая реальную задержку) без включения VPN.
- [ ] Срабатывает правило на конкретный процесс (Desktop) / приложение (Android) и домен/IP-пул; при отключении основной pinned-ноды трафик переключается на fallback-узел другого протокола.
- [ ] При создании нового профиля список правил гарантированно пуст (нет скрытых маршрутов по умолчанию).

## Фаза 4: Встроенные генераторы WARP / MASQUE и Psiphon

**Цель:** Дать пользователю встроенные бесплатные каналы связи без внешних генераторов и сайтов — по нажатию кнопки внутри клиента.

**Состав работ:**
- `core/warp`: регистрация WARP-аккаунтов, генерация профилей под **AWG 2.0 / 3.0 / 3.1** (включая расширенные параметры `I1` и пресеты обфускации по аналогии с `warp-generation.github.io`) и **MASQUE**, сканер чистых/незаблокированных Cloudflare-эндпоинтов с учетом региона.
- `core/engine/psiphon`: встраивание `psiphon-tunnel-core` с выбором страны, работой как самостоятельная нода, так и в роли резервного шага в `sticky_fallback` или цепочки (например, WARP поверх Psiphon / Psiphon поверх прокси).
- Пресеты внешних IP/доменных списков как опциональные шаблоны (подключаемые в Конструкторе только по явному клику пользователя).

**Критерии готовности (DoD):**
- [ ] Пользователь может сгенерировать рабочий профиль WARP (AWG 2/3.1 или MASQUE) в 1 клик, просканировать эндпоинты и добавить его в общий список или fallback-цепочку.
- [ ] Psiphon поднимается на Windows, Linux и Android и переключает выходную страну.

## Фаза 5: DPI-обход (ByeDPI + Zapret), Smart Hosts/DNS и ConflictGuard

**Цель:** Объединить сценарии без VPN (DPI-обход и Smart Hosts/DNS) с гибридным режимом внутри Desktop-демона и Android `VpnService`.

**Состав работ:**
- `core/engine/byedpi`: интеграция `ciadpi` для Desktop (без прав админа) и Android (`libciadpi.so` внутри того же `VpnService`, где работает VPN/маршрутизация). Редактор флагов и пресетов стратегий + локальный тестер стратегий.
- `core/engine/zapret`: управление `winws` / `WinDivert` на Windows и `nfqws` + BOM-free `nftables` на Linux, автобенчмарк стратегий, QUIC UDP 443 desync, очистка кэша Discord.
- `core/engine/smartdns`: атомарное управление `hosts` для Desktop, локальный HTTP CONNECT прокси и Smart DNS перехватчик внутри TUN на Android, синхронизация каталога DoH-провайдеров, честный пинг с защитой от Cloudflare Turnstile / Google Sorry.
- Полноценный `ConflictGuard`: детекция перекрытия `hosts` активным TUN, конфликта `WinDivert`/`nfqws` с VPN-туннелем, сторонних VPN-интерфейсов и переменных `HTTP_PROXY`/`HTTPS_PROXY` с понятным UI-разрешением конфликтов.

**Критерии готовности (DoD):**
- [ ] На Android в одном `VpnService` одновременно работают правила Конструктора: например, часть приложений через `ByeDPI`, часть доменов через `VLESS` или `WARP`.
- [ ] На Windows и Linux `Zapret` и `Smart Hosts/DNS` работают как самостоятельно (без VPN), так и корректно отслеживаются `ConflictGuard`.

**Критерии готовности (DoD):**
